# 챗봇 셋업 가이드 (에이전시 직원용)

> **이 문서는 직원이 새 클라이언트 사이트에 챗봇을 올릴 때 따라야 할 체크리스트입니다.**
> 퍼블리싱이 끝난 사이트에 한 번만 수행하면 됩니다. 이후 고객(admin02)은 관리자페이지의 '브랜드 정보' 필드로 세부 업데이트만 합니다.

---

## 역할 분담

| 역할 | 담당 | 어디서 | 수정 주기 |
|------|------|--------|-----------|
| **핵심 지식 베이스** (사이트 전체 내용) | 에이전시 직원 | `chatbot/chatbot_config.php` → `system_prompt` | 초기 1회 (대규모 리뉴얼 시 갱신) |
| **최신 보정/업데이트** (가격 변경 등) | 고객(admin02) | 관리자페이지 → '브랜드 정보' 필드 (500자) | 수시 |
| **AI 성격(말투)** | 고객(admin02) | 관리자페이지 → 'AI 성격' 4개 카드 중 선택 | 수시 |

런타임에 세 개가 합쳐져 Claude로 전달됩니다:
1. **톤 지시** (고객이 선택한 프리셋) — 최우선
2. **system_prompt** (직원 작성)
3. **브랜드 상세 정보** (고객 500자)

## AI 성격 프리셋 (고객이 선택)

- **밝고 친근** — 발랄하되 오버하지 않는 구어체 (기본값)
- **차분하고 신뢰감** — 격식 있는 전문가 톤
- **따뜻하고 공감형** — 부드러운 말투, 공감 우선
- **간결하고 사실적** — 군더더기 없이 팩트만

고객이 브랜드 포지션에 맞게 고르면 됨. 직원이 초기 세팅할 때 기본값은 **밝고 친근**으로 선택돼 있음.

## 0) 사전 준비 — 퍼블리싱 완료된 로컬/스테이징 사이트

- 홈페이지 + 모든 콘텐츠 페이지(`/bbs/content.php?co_id=*`)가 최종 시안대로 퍼블되어 있어야 함.
- DB에 `g5_content` 가 채워져 있거나, 핵심 정보가 theme HTML 안에 있어야 함.

## 1) 사이트 전체 내용 수집

### A안 — DB에서 바로 읽기 (콘텐츠가 g5_content 에 있는 경우)
```bash
mysql -uroot {PROJECT_DB} -e "SELECT co_id, co_subject, co_content FROM g5_content" \
  | sed 's/<[^>]*>//g'
```

### B안 — 렌더링된 HTML 로컬 저장
```bash
# 로컬 서버 구동 중일 때
curl -s http://localhost:8080/ > /tmp/main.html
curl -s "http://localhost:8080/bbs/content.php?co_id=brand" > /tmp/brand.html
# ... co_id 전부 순회
```

### C안 — 그냥 캡처로 전달
- 실제 사이트 스크린샷/캡처를 Claude에게 넘기고 "이 사이트로 챗봇 system_prompt 만들어줘" 요청.
- 가장 빠름. 추천.

## 2) system_prompt 작성

`chatbot/chatbot_config.php` 를 열고 `system_prompt` 의 heredoc 부분을 아래 양식에 맞춰 **다시 작성**합니다.

### 표준 양식 (복사해서 채우기)

```text
너는 {브랜드명}의 웹사이트 AI 상담사다. 대표번호 {전화번호}.
★ 브랜드명은 언제나 "{브랜드명}" (유사 표기 절대 금지).
★ 역할: 친근하고 따뜻한 상담사. 방문자가 "괜찮네" 느끼게 실 데이터를 자연스럽게 풀어주고, 전화 상담·상담 요청까지 이끌어준다.

# 브랜드 & 운영사
- {브랜드명}: {업종/카테고리 한 줄}
- 운영사 {법인명}, 대표 {대표자}
- {업력/인증/자격 등 신뢰 포인트}

# N대 경쟁력 (사이트에서 강조하는 핵심 포인트들)
1. {키워드 1}: {1~2줄 설명}
2. {키워드 2}: {1~2줄 설명}
...

# 실 데이터/실적 (사이트에 있는 구체 수치)
- {매출/매장수/실적 등 구체 숫자}
※ 정확한 수치는 상황에 따라 다를 수 있음을 고객에게 정직하게 전할 것.

# 본사/회사 지원 (고객 안심 포인트)
- {A 지원}: ...
- {B 지원}: ...

# 단계/절차 (문의 많은 주제)
1 {1단계} → 2 {2단계} → ... → N {N단계}

# 인허가/규제 체크 (해당 업종일 경우만)
- {필요 허가}
- {규제 체크포인트}

# 언론 보도 & 외부 활동 (신뢰성 포인트)
{매체명 나열}

# 운영 중 매장/지점 (해당하는 경우)
{지역별 목록}

# 문의 양식 수집 항목
이름 / 연락처 / 관심 지역 / 통화 가능 시간 / 기타

# 톤 — 발랄하되 오버하지 않음 (템플릿 기본값)
- 밝고 친근한 구어체. 딱딱한 문어체·격식 과잉 금지.
- 리액션 자연스럽게: "아, 궁금하셨구나~", "오 좋은 질문이에요" 처럼.
- 느낌표·이모지 남발 금지. 이모지는 🙂 정도로 한 답변에 1개 이하.
- 과장 금지: "최고!!" "무조건!" "완벽!" "대박!" 같은 홍보성 단어 지양.
- 너무 발랄해져 가벼워 보이지 않게 — 정보는 담백하게, 리액션만 따뜻하게.
- (업종에 따라 조정: 고급 브랜드는 격식↑, 유아/헬스는 발랄↑ 등 — 이 블록을 업종에 맞게 손질)

# 응대 스타일
- 길이: 3~5문장. [공감/리액션] → [핵심 정보: 실 데이터 + 강점] → [다음 스텝: 후속 질문 or 전화 안내].
- 답변 패턴:
  - **{자주 묻는 질문 카테고리 1}**: "{모범 답변 샘플}"
  - **{자주 묻는 질문 카테고리 2}**: "{모범 답변 샘플}"
- 관심 신호 → 단계별 정보 수집. 한 번에 폼처럼 몰아 묻지 말 것.
- 사이트에 없는 확정 수치(정확 가격·보증금·월세 등)는 추측 금지. "{전화번호}로 전화 주시면 정확한 맞춤 견적 받으실 수 있어요"로 전화 유도.
- 업무시간(09~18시) 내: "지금 바로 연결 가능해요". 시간 외: "업무시간에 전화 주시면 바로 연결돼요".
- 답변 말미마다 전화번호 안 붙여도 됨. 답이 충분하면 자연스럽게 다음 관심 포인트 질문으로 이어가기.
- 이모지는 드물게 🙂.
- 관리자가 '브랜드 정보' 필드에 추가 내용 입력 시, 그 내용을 최우선 참고.
```

### 품질 체크 — 작성 후 확인할 것

- [ ] **브랜드명 오표기 방어 규칙** 추가 — "★ 브랜드명 = 정확히 "XXX". 유사 표기(○○○, △△△) 금지"
- [ ] 사이트에 **없는 정보는 안 넣기** (가격 등 구체 숫자는 사이트에서 확인한 것만)
- [ ] 타사 전화번호/브랜드명 누락 확인 (ex. 복붙 실수 방지)
- [ ] 응대 스타일의 "답변 패턴" 섹션은 **자주 묻는 2~4개 질문에 대한 모범 답변 샘플** 포함 — Claude가 톤·길이 잡는 기준이 됨
- [ ] **총 길이 2500자 전후 권장** (± 200자). 이 분량이 품질과 토큰의 균형점.
  - 너무 짧으면(<1500자) → 답변 깊이 부족
  - 너무 길면(>3500자) → 프롬프트 캐싱이 있어도 첫 호출 비용 + 답변 속도 저하
- [ ] `brand_info` 관리자 필드(500자)와 **중복 서술 금지** — 고객이 자주 바꿀 정보(가격/이벤트/전화번호 등)는 `brand_info` 쪽으로 미루고, `system_prompt`는 뼈대(브랜드 정체성·핵심 경쟁력·응대 스타일)만

## 5) 첫 배포 후 관리자 초기 설정

1. 사이트 FTP 업로드 완료 → `https://{domain}/adm/` 로 admin 로그인
2. `https://{domain}/chatbot/chatbot_admin.php?page=settings` 이동
3. **MASTER 섹션**에서:
   - 사용 여부 **사용함** 토글 ON
   - 사용 기간 선택 (고객이 계약한 개월 수)
   - 저장
4. **고객사 필드**에서:
   - 브랜드명 / 전화번호 / 알림 이메일 확인
   - 빠른 질문 확인
   - 환영 메시지 입력 (예: `"안녕하세요! {브랜드} AI 상담사예요. 궁금하신 점을 편하게 물어보세요!"`)
   - 저장

## 6) 테스트 체크리스트

- [ ] 홈페이지 좌측 하단에 위젯 아이콘이 보임
- [ ] 위젯 클릭 → 환영 메시지 + 빠른 질문 4개 보임
- [ ] 빠른 질문 클릭 → AI가 3~5문장, 실데이터 포함 답변
- [ ] 답변 말미 톤이 영업적으로 과하지 않음
- [ ] 답변 중 오표기(유사 브랜드명) 없음
- [ ] "대략 비용이 얼마에요?" 같이 구체 질문 → 정확 수치 없을 땐 "전화 주세요" 유도
- [ ] 연락처 입력 (예: `010-1234-5678`) → 관리자 페이지 설정한 알림 이메일로 수신
- [ ] 30초~1분 정도 대화 후 3번째 메시지쯤 "상담사 연결 받으시겠어요?" 폼 나타남
- [ ] 위젯 X 버튼 → 닫힘
- [ ] 새로고침 후에도 대화 기록 유지됨 (sessionStorage)
- [ ] 모바일(599px 이하)에서도 위젯 정상 노출
- [ ] 관리자 페이지 상담 내역에 대화 기록이 들어감
- [ ] 검색 / 날짜 필터 / 연락처 남긴 상담만 필터 정상 작동
- [ ] 상담 개별 삭제 버튼 정상 작동

## 비용 가이드 & 토큰 절약 원칙

### 모델·단가
- **Claude Haiku 4.5**: $1 / $5 per 1M tokens (input / output). 가장 저렴한 SOTA.
- **프롬프트 캐싱 적용됨** (5분 TTL) — 동일 `system_prompt` 재사용 시 input **비용 90% 할인**. 대화가 이어질 때 자동으로 혜택.

### 1회 상담 평균 (2500자 system_prompt 기준)
- 첫 메시지: input ~1800 tokens (캐시 miss) + output 300 tokens ≈ **$0.0033** (약 5원)
- 이어지는 메시지: input ~180 tokens (캐시 hit 90% 할인) + output 300 tokens ≈ **$0.0017** (약 2.5원)
- 월 100회 상담, 각 5턴 대화 기준 → **월 500원 이하**

### system_prompt 작성 시 토큰 절약 원칙
1. **반복 금지** — 같은 브랜드명/전화번호 5번 나오면 Claude가 이미 기억함. 2~3번으로 충분.
2. **마크다운 미니멀** — `#` 1단만, 중첩 리스트 금지. 읽히기만 하면 됨.
3. **예시는 1개만** — "답변 패턴"에 FAQ별 모범 답변 넣을 때 각 카테고리마다 샘플 1개씩. 2~3개 넣으면 토큰 폭증.
4. **장식어 제거** — "매우/많이/굉장히/정말" 빼도 의미 안 변하면 빼기.
5. **중복 서술 금지** — `brand_info` DB 필드가 뒤에 자동 합쳐지므로, 자주 바뀔 정보(가격/이벤트)는 그쪽에 넘기고 system_prompt에 안 씀.

### 주의
- `brand_info` 관리자 필드(500자)는 매 호출마다 system에 병합됨 — 캐싱 효과를 받으려면 이 값도 자주 바꾸지 말 것 (바꾸면 캐시 무효화).
- 1일 30회 미만으로 상담 없는 날은 캐시 만료돼 매번 miss 발생 → 위 비용 추정은 5턴 대화 기준.
